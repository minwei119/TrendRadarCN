# TrendRadarCN 使用文档

面向**使用者**：如何安装、启动、查看中文互联网热点数据。
（想排查报错、调试源，请看同目录的 [调试文档.md](调试文档.md)。）

---

## 1. 这是什么

一个本地运行的爬虫 + 统计系统，抓取中文互联网各大平台的热门话题，保存为
"快照"，并提供仪表盘看排行榜与跨平台聚合趋势（类似谷歌趋势的本地版）。

数据源：微博、百度、今日头条、B 站、掘金、知乎、V2EX、NodeSeek。

## 2. 第一次安装

需要 **Python 3.11 或更高版本**（3.9 会报 `unsupported operand type(s) for |`）。

```powershell
cd C:\Users\minwei\TrendRadarCN

# 建虚拟环境（用 3.13）
py -3.13 -m venv .venv
.venv\Scripts\activate          # 成功后提示符前会出现 (.venv)

# 升级 pip 工具链
python -m pip install --upgrade pip setuptools wheel

# 装依赖（强制只用预编译包，避免编译 greenlet 失败）
pip install --only-binary=:all: -r requirements.txt
```

确认环境正确：

```powershell
python --version        # 应为 3.13.x
where.exe python        # 第一行应是 .venv\Scripts\python.exe
```

## 3. 启动与查看结果（最常用）

```powershell
.venv\Scripts\activate
python run.py
```

看到 `Uvicorn running on http://127.0.0.1:8001` 后，浏览器打开
**<http://127.0.0.1:8001>**，然后：

1. 点右上角 **「立即抓取」** —— 触发一次全平台抓取（几秒到 1 分钟）
2. 抓完页面自动刷新，你会看到三块内容：

| 区块 | 内容 |
| ---- | ---- |
| **综合热度榜** | 跨平台加权聚合。出现在多个平台的话题排名靠前——这是看"破圈"热点的最佳视角 |
| **各平台热榜** | 每个平台独立的 top 列表；点任意话题 → 弹出它的**历史排名趋势曲线** |
| **最近抓取记录** | 每次任务的成功/失败、条数、耗时、错误信息 |

> 趋势曲线需要**多次抓取**才有数据：同一话题在多个时间点的快照里都出现，才能连成线。
> 想看趋势，就隔一段时间多点几次「立即抓取」。

按 `Ctrl+C` 停止服务。

## 4. 抓取结果存在哪 / 怎么查看

所有数据写入项目根目录的 SQLite 文件 **`trendradar_cn.db`**。三种查看方式：

### 方式 A：仪表盘（见上一节）

### 方式 B：HTTP API（返回 JSON）

服务启动后直接在浏览器或用 `curl` 访问：

| 地址 | 说明 |
| ---- | ---- |
| `http://127.0.0.1:8001/api/hot` | 所有源最新快照的话题列表 |
| `http://127.0.0.1:8001/api/hot?source=weibo` | 只看微博 |
| `http://127.0.0.1:8001/api/aggregate?hours=24` | 近 24 小时综合加权榜 |
| `http://127.0.0.1:8001/api/trend?title=XXX` | 某话题的历史排名 |
| `http://127.0.0.1:8001/api/snapshots` | 最近抓取记录 |
| `http://127.0.0.1:8001/api/logs?limit=100` | 最近的请求日志 |
| `http://127.0.0.1:8001/docs` | 交互式 API 文档，可在线点测 |

### 方式 C：直接读数据库

```powershell
python - <<'PY'
import sqlite3
con = sqlite3.connect("trendradar_cn.db")
for src, title, rank in con.execute(
    "SELECT s.source_key, t.title, t.rank "
    "FROM topics t JOIN snapshots s ON t.snapshot_id = s.id "
    "ORDER BY s.fetched_at DESC, t.rank LIMIT 20"
):
    print(f"{src:10s} #{rank:<3} {title}")
PY
```

## 5.5 主题板块（按主题/行业的每日简报）

除了"哪些话题最火"的平台热榜，你还可以按**主题**看新闻——比如股市要闻、
AI 行业动态、自定义关键词板等。

**仪表盘里点顶部「主题板块」 Tab**，选一个板块就能看当日文章列表。

**命令行单独跑一个板块：**

```powershell
python run.py --board stocks-cn       # 只跑股市板
python run.py --board ai-frontier     # 只跑 AI 前沿板
python run.py --board all             # 跑所有板块
```

**怎么加/改板块？** 直接编辑 `app/boards/boards.yaml`——不用写代码、不用重启服务。
板块支持 **4 种** 数据源类型，可按需混搭：

| 类型 | 用法 | 用途 | 是否需代理 |
| ---- | ---- | ---- | ---- |
| `rss` | 给 `url` | 任意 RSS 2.0 或 Atom 源（SEC EDGAR / 36kr 等） | 看具体 URL |
| `google_news` | 给 `query` + `lang` + `country` | Google News 搜索（最方便，覆盖广） | **是** |
| `crawler` | 给现有 `source` key | 复用已有平台抓取（如从微博热搜里筛关键词） | 否（本地查表） |
| `json_api` | 给 `url` + `list_path` + `fields` | 任意 JSON 接口（华尔街见闻 / 雪球 / 东财） | 看具体接口 |

### 当前 4 个板块的源构成（v2，已减少 Google News 依赖）

| 板块 | 直连源（无需代理） | 备份源（走代理） |
| ---- | ---- | ---- |
| 股市要闻 | 华尔街见闻 7×24 (json_api)、新浪财经 RSS、微博/头条 | Google News × 2 |
| 我的持仓 | 雪球 00700/09988 (json_api)、SEC EDGAR · BABA (Atom) | Google News × 2 |
| AI 前沿 (中文) | 36kr 快讯、极客公园；可启用 RSSHub 提供 5 家 | Google News × 2 |
| AI Frontier (英文) | TechCrunch · AI、MIT Tech Review · AI | Google News × 2 |

即使 Google News 一条不通，板块也能跑出结果。代理通了则数据更全。

### 加一个新公司到「我的持仓」

**港股**（雪球 json_api）：复制现有的雪球 feed，改 `symbol`：

```yaml
- type: json_api
  label: 雪球 · 美团 (03690)
  url: https://stock.xueqiu.com/v5/stock/portfolio/stock/timeline.json?symbol=03690&size=20&page=1
  list_path: data.list
  fields:
    title: title
    url: target
    summary: description
    published_at: created_at
  url_template: "https://xueqiu.com{target}"
  headers:
    Referer: https://xueqiu.com/S/03690
```

**美股 ADR**（SEC EDGAR Atom）：把 `CIK=` 换成新公司的 [CIK 编号](https://www.sec.gov/cgi-bin/browse-edgar?action=getcompany)：

```yaml
- type: rss
  label: SEC EDGAR · 京东 JD
  url: https://www.sec.gov/cgi-bin/browse-edgar?action=getcompany&CIK=0001549802&type=&owner=include&count=40&output=atom
```

### 用 LLM 打标签（替代关键词规则）

关键词规则简单但容易误判（"英伟达 CEO 离职" 也被打 AI芯片）。每个板块可以单独
切换到 LLM 分类，在 yaml 里加一行：

```yaml
- key: ai-cn
  tagger: llm    # 默认 rule，改成 llm
  tags:
    大模型: [GPT, Claude, Llama, 大模型, LLM]
    AI芯片: [H100, MI300, 算力, 加速器]
    ...
```

设环境变量后用：

```powershell
$env:TRENDRADAR_LLM_API_KEY = "sk-..."     # DeepSeek / Moonshot / OpenAI 等
# $env:TRENDRADAR_LLM_BASE_URL = "https://api.deepseek.com"  # 默认 DeepSeek
# $env:TRENDRADAR_LLM_MODEL    = "deepseek-chat"             # 默认

# 切了 tagger 之后，清空老标签，让 LLM 重新打一遍
python run.py --reset-tags ai-cn
python run.py --backfill-boards
```

控制台会输出每次 LLM 调用的 token 用量 + 预估成本（DeepSeek 默认价：约 $0.05/千篇）。

**关键词列表的角色**：rule 模式下是匹配规则；LLM 模式下作为「语义提示」传给模型理解
标签含义，模型 NOT 用关键词字面匹配。所以即使关键词没列全，LLM 也能根据标签名
（比如「AI芯片」）正确分类内容。

### 用 LLM 生成一句话摘要

很多 RSS / 论文源的标题写得晦涩（"GR-3: A Generalist Vision-Language-Action Model"
这种），原文摘要又长。`summarizer: llm` 让模型给每条新闻生成一句话总结
（中文 ≤60 字 / 英文 ≤25 词），存到 `articles.llm_summary` 列，**不会动**原始
`summary`。Web 仪表盘里以小字灰色显示在标题下方；邮件早报里也优先用 LLM 摘要。

在 `boards.yaml` 给某个板块开启：

```yaml
- key: ai-cn
  tagger: llm           # 已有
  summarizer: llm       # 新增这一行就够了
  ...
```

默认仓库里 `ai-cn` / `ai-frontier` / `robotics` 三个板已开启；股票类板块标题通常已经
够清晰，没必要花钱再总结，所以没开。

环境变量复用 tagger 的：`TRENDRADAR_LLM_API_KEY` (或 `DEEPSEEK_API_KEY`)。可选：
`TRENDRADAR_LLM_SUMMARY_BATCH` (默认 5) / `TRENDRADAR_LLM_SUMMARY_CONCURRENCY` (默认 4)。

```powershell
# 给已经入库但还没摘要的文章补摘要 (3 个 AI 板)
python run.py --backfill-summaries

# 重新摘要全部 (会清空已有 llm_summary 再重跑)
python run.py --backfill-summaries --force

# 只清掉某板的摘要 (下次 backfill 会重新生成)
python run.py --reset-summaries ai-cn
python run.py --reset-summaries all
```

成本估计：DeepSeek-V3 默认价下，约 **$0.0001 / 篇**（一句话输入+输出 < 200 token）。
3 个板每天 100-200 篇新文章，日均花费 **< $0.02**。控制台会按板块打印 token 用量
和美元成本。

`tagger` 和 `summarizer` 互不依赖，可以分别开关；它们用同一个 API key 同一个模型，
打标签和写摘要并行调用，每个板块多花一次 LLM round trip 的时间（典型 3-8 秒）。

### 用 LLM 合并重复事件（邮件早报专用）

入库时的字符 bigram 相似度（`app/boards/dedup.py`）能合并**近似措辞**的标题
（"央行降准 0.5%" 和 "重磅！央行降准 0.5 个百分点 释放万亿流动性"），但**抓不到**
语义重复——比如同一事件三家媒体用完全不同的角度报道：

```
小米发布 CyberOne 2 人形机器人
雷军：小米 CyberOne 售价 19.9 万
小米机器人对标 Tesla Optimus
```

这三条字符层面差别很大，bigram Jaccard 算出来低于阈值，但其实是**同一事件**。

**做了什么。** 生成邮件早报时，每个板块取最新最热的 20 条候选（已按入库时的
`cluster_id` 预聚合），把这些代表条目（id + 标题 + LLM 摘要）一次性发给 DeepSeek
让它给出语义分组，再合并成 top 8 组渲染到邮件里。每组邮件正文显示
`3 sources: 36kr · 钛媒体 · 量子位`，让你一眼看出哪些事件是被多家媒体同时报道的
"破圈"事件。

**自动触发。** 你跑 `python run.py --board all --email` 时早报构建里会自动调用，
没有额外开关。前提是 `TRENDRADAR_LLM_API_KEY`（或 `DEEPSEEK_API_KEY`）已配置。

**兜底行为。** 如果 LLM 调用失败（key 失效、网络、超时、JSON 解析失败），早报会
**降级**到只用入库时的 `cluster_id` 预聚合，跟没启用这个功能时的行为一模一样。
不会让早报发不出来。

**不动 web 仪表盘。** 这一步**只在邮件早报时跑**，仪表盘的文章列表仍然按入库时的
`cluster_id` 显示，不会因为加了这层语义聚合而被改写。数据库 `articles.cluster_id`
列也**不会**被修改。

**先看看再发。** 加了一个不发邮件的预览命令：

```powershell
python run.py --digest-preview
```

它会构建早报但不发，打印 subject、每个板块的最终 group 数、每个板块的 LLM 用量，
以及每板块前 3 条样例（plain text 格式）。

**用现有数据立即发一封。** 不想等抓取（5 分钟）就想测邮件渲染或者页脚链接：

```powershell
python run.py --digest-send
```

读当前 DB，构建早报，直接发到 `SMTP_TO`。10 秒搞定，跟 `--board all --email`
出来的邮件**内容一致**，只是不重新抓数据。

**成本估计。** 单次邮件早报里每个板块一个 LLM round trip：20 条候选 × （标题 + 一句话
LLM 摘要） ≈ 1500-3000 tokens 输入、100-300 tokens 输出，DeepSeek-V3 默认价约
**$0.001 / 板块 / 次**。5 个板块每天一次早报 ≈ **$0.005 / 天** 或 **$0.15 / 月**。
控制台日志（`logs/crawl.jsonl`）的 `source=llm-cluster` 记录里能看到每次的实际用量。

### 在仪表盘里也应用语义聚类

之前 LLM 语义聚类**只在生成邮件早报时跑**, 仪表盘还是按入库时的 `cluster_id`
（字符 bigram 相似度）展示, 所以同一焦点的多家媒体报道在 web 上仍然会显示成一长串
（典型现场: my-portfolio 板里 10+ 条阿里新闻）。

现在改成**入库后立即跑一次** LLM 聚类, 把结果持久化到 `articles.llm_cluster_id` 列。
邮件早报和仪表盘都优先按这一列分组, 行为完全一致：

- **自动**: `python run.py --board <key>` 抓完后自动对最近 72 小时的文章跑一次
  LLM 聚类, 控制台会打印 `[llm-cluster] <board> input=N groups=M cost=$0.000X updated=K`。
- **手动重跑** (改了 prompt 想重新分组): `python run.py --apply-llm-cluster <board>`
  或 `--apply-llm-cluster all`。
- **从头来过** (彻底丢弃旧的 LLM 分组): 加 `--force`, 会先把
  `llm_cluster_id` 清成 `NULL` 再跑。
- **digest 不会再花一次钱**: 早报构建时检测到所有候选都已经有 `llm_cluster_id`,
  就直接读, 不再调一次 LLM。终端打印
  `(persisted llm_cluster_id: input=...)` 表示走了快路径。

成本相比之前**约持平**: 之前邮件每天一次 LLM 调用, 现在抓取时一次, 邮件 0 次。
跑 `python run.py --apply-llm-cluster <board>` 可以重复执行而保持稳定:
`llm_cluster_id` 取每组里 `min(article.id)`, 同一组文章只要还在 72h 窗口里, 重新跑
得到的值就一样。

底线: 失败 (key 失效 / 网络 / JSON 解析失败) 时**绝不抛异常**, 只把错误打印到控制台、
返回 stats 里带 `error` 字段。`--board` 抓取本身不会被这一步搞挂。

### 给 AI 前沿 (中文) 加稳定的中文媒体源 (RSSHub)

机器之心 / 量子位 / 智东西 / 新智元 都没有官方 RSS。最干净的办法是本机起一个
RSSHub（项目根目录已有 `docker-compose.rsshub.yml`）：

```powershell
docker compose -f docker-compose.rsshub.yml up -d
```

然后编辑 `app/boards/boards.yaml`，把 ai-cn 板块里 "自建 RSSHub 后启用"
那几行的 `#` 去掉，重新跑 `python run.py --board ai-cn` 即可。

详见调试文档 §10。

### 公网仪表盘快照（GitHub Pages）

邮件页脚的"仪表盘"链接默认是 LAN IP（只能同 WiFi 点）。想让任何网络都能打开
（含 126 / Gmail 网页邮箱里点邮件链接），用 GitHub Pages 托管每日静态快照。

CLI：

```powershell
python run.py --snapshot              # 仅生成 docs/index.html (不 push)
python run.py --snapshot-publish      # 生成 + git add + commit + push origin HEAD
```

生成的 HTML 自包含（Tailwind CDN + 内联 JSON 数据），双击 `docs\index.html`
就能在浏览器里看完整效果。

一次性配置（详见 [README.md](../README.md#公网访问推荐github-pages-静态快照)）：

1. `python run.py --snapshot-publish` 初次推送
2. GitHub 仓库 Settings → Pages → Branch: `main` / Folder: `/docs` → Save
3. 把 GitHub 给的 `https://<user>.github.io/<repo>/` 填到 `.env` 的
   `TRENDRADAR_PUBLIC_URL`（优先于 `TRENDRADAR_DASHBOARD_URL`）

之后每天 7:30 计划任务里的 `scripts\run_boards.ps1` 会自动跑
`--board all --email --snapshot-publish`，把当天数据推上 GitHub，
Pages 自动重新发布；邮件页脚链接自动指向公网 URL。

幂等：连续两次跑 `--snapshot-publish` 而数据库没新内容，第二次会打印
`[snapshot] nothing to publish` 并干净退出 0。

## 7. 常见操作

**改端口**（默认 8001）：

```powershell
python run.py --port 9001
```

**配代理**（让 v2ex/nodeseek 等走代理）：

```powershell
$env:TRENDRADAR_PROXIES = "http://127.0.0.1:7890"   # 换成你的端口
python run.py
```

**清空数据重来**：停止服务后删除 `trendradar_cn.db`，下次启动会自动重建。

**定时抓取**：用 Windows「任务计划程序」定时执行
`C:\Users\minwei\TrendRadarCN\.venv\Scripts\python.exe run.py --crawl`。

## 8. 全部可调环境变量

详见 [README.md](../README.md) 的"代理与重试"/"请求日志"两节，常用的：

| 变量 | 作用 | 默认 |
| ---- | ---- | ---- |
| `TRENDRADAR_PROXIES` | 代理列表（逗号分隔，轮换） | 空 |
| `TRENDRADAR_MAX_RETRIES` | 失败重试次数 | 2 |
| `TRENDRADAR_MIN_INTERVAL` | 同站请求最小间隔秒数 | 0 |
| `TRENDRADAR_ZHIHU_COOKIE` | 知乎登录 cookie（兜底） | 空 |
| `TRENDRADAR_LOG_CONSOLE` | 把请求日志同时打到终端 | false |

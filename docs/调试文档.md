# TrendRadarCN 调试文档

面向**排查问题**：如何测试系统、读懂错误、定位某个源为什么挂。
（只想正常使用，请看 [使用文档.md](使用文档.md)。）

---

## 1. 三层验证

| 层级 | 命令 | 作用 | 是否联网 |
| ---- | ---- | ---- | ---- |
| ① 单元测试 | `pytest` | 验证解析/重试/配置逻辑正确 | 否 |
| ② 冒烟测试 | `python run.py --crawl` | 真抓一遍，看哪些源通 | 是 |
| ③ 端到端 | `python run.py` + 浏览器 | 验证 Web/API/数据库 | 是 |

排查顺序：**先 ① 确认代码没问题，再 ② 看是哪个源、什么错，最后针对性修。**

---

## 2. 跑单元测试

```powershell
.venv\Scripts\activate
pip install -r requirements-dev.txt
pytest
```

期望输出类似 `8 passed`。覆盖：代理候选解析、429 重试、404 立即放弃、
微博/V2EX 解析等。**如果这层失败**，说明是代码 bug（而非网络），把完整输出贴出来。

> 注意：终端里复制 `8 passed in 4s` 这种**结果行**不要再粘回去执行——那是输出不是命令，
> 会报 `Unexpected token`。

只跑某个测试文件：

```powershell
pytest tests/test_crawlers.py -v
```

## 3. 看请求日志（定位哪个源不稳定）

每次 HTTP 请求都写一行 JSON 到 `logs/crawl.jsonl`。字段：源、host、状态码、
用没用代理、第几次尝试、耗时、错误。

**只看失败的：**

```powershell
Get-Content logs\crawl.jsonl -Tail 100 | Select-String '"ok":false'
```

**或通过 API：** `http://127.0.0.1:8001/api/logs?limit=100`（最新在前）。

**想抓取时在终端实时看每个请求：**

```powershell
$env:TRENDRADAR_LOG_CONSOLE = "1"
python run.py --crawl
```

## 4. 错误码对照表

抓取摘要或日志里的 `error` 字段，对照下表判断性质：

| 错误 | 含义 | 性质 | 解决方向 |
| ---- | ---- | ---- | ---- |
| `items=0` 但状态 OK | 请求成功但没解析出数据 | **代码/接口变化** | 接口结构变了，需更新解析（见 §6） |
| `HTTPStatusError 401` | 需要鉴权 | 反爬 | 提供 cookie（见 §5 知乎） |
| `HTTPStatusError 403` | 被 WAF 拦截 | 反爬 | 补浏览器头/cookie，或换 IP |
| `HTTPStatusError 429` | 请求太频繁 | 限频 | 已自动重试；可调高 `TRENDRADAR_MIN_INTERVAL` |
| `ConnectTimeout` | 能解析域名但连不上 | **网络/被墙** | 配代理 |
| `getaddrinfo failed` (11002) | 域名解析失败 | **DNS 被屏蔽** | 换 DNS 或配代理（见 §7） |
| `ConnectError` 其它 | 连接被拒/网络中断 | 网络 | 检查网络/代理 |

## 5. 各源已知问题与排查

### 知乎（zhihu）— 反爬最严

现象：`401`（API 要签名）或 `403`（WAF 拦 billboard）。
程序已自动尝试：补浏览器头 + 先访问首页种游客 cookie + 回退 billboard 页面解析。
若仍失败，用**登录 cookie**（最稳）：

1. 浏览器登录 zhihu.com
2. F12 → Network → 刷新 → 点最上面的 `www.zhihu.com` 请求 → Request Headers →
   复制 `cookie:` **整行的值**
3. 设环境变量后重跑：

```powershell
$env:TRENDRADAR_ZHIHU_COOKIE = "粘贴整段cookie"
python run.py --crawl
```

带 cookie 时会优先走官方 v3 API。

### V2EX / NodeSeek — 域名可能被 DNS 屏蔽

现象：`getaddrinfo failed`。先确认：

```powershell
nslookup www.v2ex.com
nslookup www.nodeseek.com
```

- 解析失败或返回异常 IP → DNS 被干扰。解决：
  1. 换公共 DNS（网络适配器 → DNS 改 `223.5.5.5` 或 `119.29.29.29`），然后 `ipconfig /flushdns`
  2. 或配代理 `$env:TRENDRADAR_PROXIES`
- NodeSeek 还可能遇 Cloudflare 盾（返回 403/challenge），那需要带 cookie，暂不支持自动绕过。

## 6. 单独调试一个源

**只抓一个源**（服务启动后）：

```powershell
curl.exe -X POST "http://127.0.0.1:8001/api/crawl?source=baidu"
```

**直接在 Python 里调该源的 fetch()，看原始结果或异常：**

```powershell
python - <<'PY'
import asyncio
from app.crawlers.baidu import BaiduCrawler
items = asyncio.run(BaiduCrawler().fetch())
print("条数:", len(items))
for it in items[:5]:
    print(it.title, "|", it.score, "|", it.url)
PY
```

**抓到的是 0 条但请求成功** → 多半是接口/页面结构变了。打印原始响应看结构：

```powershell
python - <<'PY'
import asyncio, httpx
async def main():
    async with httpx.AsyncClient(timeout=15, follow_redirects=True,
        headers={"User-Agent":"Mozilla/5.0"}) as c:
        r = await c.get("https://top.baidu.com/api/board?platform=pc&tab=realtime")
        print(r.status_code)
        print(r.text[:800])
asyncio.run(main())
PY
```

对比新结构，更新对应 `app/crawlers/xxx.py` 里的解析字段即可。

## 7. 网络与代理排查

**测试代理对某站是否有效**（设进程序前先单独验证）：

```powershell
curl.exe -x http://127.0.0.1:7890 https://www.v2ex.com/api/topics/hot.json --max-time 15
```

- 有返回 → 代理可用，用 `$env:TRENDRADAR_PROXIES="http://127.0.0.1:7890"` 重跑
- 超时 → 代理本身没覆盖该站（检查 Clash/V2Ray 规则或开全局模式）

**确认环境变量在当前会话生效**：设变量和跑程序必须在**同一个** PowerShell 窗口。
检查：`echo $env:TRENDRADAR_PROXIES`。

## 10. 主题板块调试

板块系统在 `app/boards/`，配置在 `boards.yaml`。

**单跑一个板块看每个 feed 的成功/失败：**

```powershell
python run.py --board stocks-cn
```

输出示例：

```
  [OK ] stocks-cn  feeds=3/4  new= 12  seen= 47
  ! google_news:GNews · A股政策: ConnectTimeout:
```

> `feeds=3/4` 表示 4 个数据源里 3 个成功；`new=12` 是本次新增（去重后），
> `seen=47` 是抓回并通过过滤后的总条数。

**常见问题对照：**

| 现象 | 原因 | 解决 |
| ---- | ---- | ---- |
| 所有 google_news feed 都 timeout | Google News 没走代理 | `$env:TRENDRADAR_PROXIES = "http://127.0.0.1:7890"` 再跑；如果板块还有直连源，板块整体仍可工作 |
| `crawler` 类型 feed 出 0 条 | 引用的 source 还没抓过 | 先 `python run.py --crawl` 把基础平台抓一遍 |
| `json_api` feed 出 0 条 | URL 通了但 `list_path` / `fields` 路径不对 | 看下面"调试 json_api 接口"小节 |
| 雪球 `400 Bad Request` | 缺 session cookie | yaml 里加 `warmup_url: https://xueqiu.com/S/00700` 自动拿 cookie；仍 400 就手动塞 `headers.Cookie` |
| 雪球 `400` 且已有 warmup | 雪球升级了风控 | F12 复制完整 Cookie 到 `headers.Cookie` 兜底（同知乎方案） |
| SEC EDGAR `403 Forbidden` | UA 没标明邮箱（SEC 风控） | yaml 里加 `headers.User-Agent: "YourApp your@email.com"` (SEC 公开政策强制要求) |
| RSS feed `ConnectTimeout` 偶发 | 国内站点慢，超过默认 12s | 板块 fetcher 已经用 20s 超时；如还超时则站点访问性问题，换源或加代理 |
| 跑成功但 articles_new=0 | 标题命中了 `exclude` 或全没命中 `include` | 调整 `boards.yaml` 的过滤词，include 空表示"全收" |
| `unknown feed type` | yaml 里写错了 type | 只能是 `rss` / `google_news` / `crawler` / `json_api` |
| 改了 yaml 没生效 | 板块定义每次运行重读，但服务端缓存了 boards summary | 刷新页面/重跑 `--board` 即可（不用重启服务） |

**单独测某个 RSS URL 能不能解析：**

```powershell
python -c "import asyncio; from app.boards.fetchers import fetch_rss; items = asyncio.run(fetch_rss('https://techcrunch.com/category/artificial-intelligence/feed/', 'test')); print('条数:', len(items)); [print(it.title, '|', it.url) for it in items[:3]]"
```

**调试 json_api 接口（新加源时最常用）：**

先用浏览器或 curl 看一下接口返回的 JSON 结构，确认 `list_path` 该写啥：

```powershell
# 1. 看返回的 JSON 长啥样
curl "https://api-one.wallstcn.com/apiv1/content/lives?channel=global-channel&client=pc&limit=3" | python -m json.tool

# 2. 直接调 fetcher
python -c "import asyncio; from app.boards.fetchers import fetch_json_api; r = asyncio.run(fetch_json_api(url='https://api-one.wallstcn.com/apiv1/content/lives?channel=global-channel&client=pc&limit=5', label='wscn', list_path='data.items', fields={'title':'title','url':'uri','summary':'content_text','published_at':'display_time'}, url_template='https://wallstreetcn.com/livenews/{id}')); print('条数:', len(r)); [print(x.title[:40], '|', x.url) for x in r[:3]]"
```

**带 cookie 的 json_api（warmup_url 用法）：**

```yaml
- type: json_api
  label: 雪球 · 美团
  url: https://stock.xueqiu.com/v5/.../timeline.json?symbol=03690
  warmup_url: https://xueqiu.com/S/03690   # 先访问首页拿 cookie
  headers:
    Referer: https://xueqiu.com/S/03690
  list_path: data.list
  fields: { title: title, url: target }
```

工作原理：板块 fetcher 在同一个 `httpx.AsyncClient` 内先 GET `warmup_url`
（cookies 自动落到 client），再 GET 真正的 API。代理、UA、超时都会沿用。
适用站点：雪球、知乎、所有"先访首页才能用 API"的站。

**LLM 分类器调试（tagger: llm 的板块）：**

```powershell
# 看 key 设了没
echo $env:TRENDRADAR_LLM_API_KEY

# 跑 1 次板块，控制台会有一行类似：
#   llm[ai-cn]: tagged=23/30 batches=3 tokens=2840+412 usd=0.00122
python run.py --board ai-cn

# 看 obs 日志 (每个 batch 一条记录)
python -c "import json; [print(json.dumps(r, ensure_ascii=False)) for r in json.loads(__import__('app.obs', fromlist=['read_recent']).read_recent(50)) if r.get('source')=='llm-tagger']"
```

| 现象 | 原因 | 解决 |
| ---- | ---- | ---- |
| `tagged=0/N` | 模型返回的标签都不在候选列表里 (大小写或换行问题) | 看 obs 日志里返回的 content，校对 yaml 标签名 |
| `errors=N` (batch 数) | API 超时/限流/key 失效 | 减并发: `$env:TRENDRADAR_LLM_CONCURRENCY = "2"` |
| `401 Unauthorized` | key 错或没设 | `echo $env:TRENDRADAR_LLM_API_KEY` 检查 |
| 模型返回非 JSON | 不支持 `response_format: json_object` | 换支持的模型: `deepseek-chat`, `gpt-4o-mini`, `glm-4-flash` |
| 标签和你的预期不符 | system prompt 没说清你想要的标准 | 在 yaml 关键词里加更明确的"例子"作为语义提示 |

## 11. 加了新源后怎么调试

1. 在 `app/crawlers/` 新建 `xxx.py`，继承 `BaseCrawler`，实现 `async fetch()`，
   内部用 `await self.get(url)` / `self.post(...)`（自动获得重试+代理+日志）。
2. 在 `app/crawlers/__init__.py` 的 `_REGISTRY` 注册实例。
3. 用 §6 的 "直接调 fetch()" 方式单测，确认能解析出条数。
4. 重启服务（会自动把新源插入 `sources` 表）。
5. 给它在 `app/static/index.html` 的 `SOURCE_COLORS` 加个颜色徽章（可选）。
